Single-process Node.js application with four cohesive modules:
- `index.js` — Express entry point mounting CORS/JSON/multer middleware, defining the `/api/*` REST surface (repos CRUD, jobs polling, authors, metrics, commits, merge/unmerge), and optionally serving a prebuilt client from `../client/dist`.
- `ingest.js` — Background job pipeline: spawns external `git` (`clone --bare`, single `git log HEAD --no-merges -M50% --numstat` with a custom `@@RAT@@` marker format) and `unzip`, streaming stdout to build an in-memory representation of `{head, paths, pathIndex, ancestors, isDir, commits, baseAuthors}`, then persists via `Store.addRepo`. Jobs are tracked in a process-wide `jobs` Map and polled via `GET /api/jobs/:id`.
- `store.js` — `Store` class owning the on-disk layout under `data/`: `registry.json` (in-memory `metas` + persisted), per-repo JSON cache files under `data/cache/<id>.json`, bare git repos under `data/repos/<id>/`, and temp uploads under `data/tmp/up/`. Manual author merges live only in registry metadata and are applied at query time via `applyMerge`.
- `metrics.js` — Pure aggregation engine over the parsed repo model: `selectCommits` filters by author/date/hash/path, `computeMetrics` does one pass producing file/dir/author/timeline summaries capped at `CAP_FILES=1500`, `CAP_DIRS=1500`, `CAP_AUTHORS=400`; results are cached in `Store.mcache` keyed by `repoId|params`.

Dependency direction is strictly `index.js → {ingest.js, store.js, metrics.js}`; there are no cross-imports among the three leaf modules. External tooling (`git`, `unzip`) is invoked as child processes rather than through libraries.
